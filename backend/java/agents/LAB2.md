# Лабораторная работа №2. Типы поведения агентов JADE

Цель: изучить поведения агентов, поиск сервисов через DF и обмен ACL-сообщениями на примере торговли книгами.

## Запуск

Из папки `backend/java/agents`:

```powershell
mvn -Plab2 compile exec:java
```

Для IntelliJ IDEA: Main class — `jade.Boot`, classpath модуля `agents`, Program arguments:

```text
-gui -local-host 127.0.0.1 -agents seller1:bookTrading.BookSellerAgent;seller2:bookTrading.BookSellerAgent;seller3:bookTrading.BookSellerAgent;buyer1:bookTrading.BookBuyerAgent(Java_programming);buyer2:bookTrading.BookBuyerAgent(Clean_code)
```

Сначала остановите предыдущую платформу JADE, если порт 1099 занят.
Обычный запуск без профиля lab2 по-прежнему запускает первую лабораторную.

## Опыт с несколькими продавцами и покупателями

У покупателей также есть окно с журналом поиска, ценами продавцов и результатом покупки. Если название передано в Arguments, поиск начинается автоматически. Чтобы вводить книгу вручную, запускайте покупателя без аргументов: `buyer1:bookTrading.BookBuyerAgent`. Введите название и нажмите «Купить». После покупки агент завершается, а окно остаётся открытым для просмотра результата. Для следующей покупки создайте нового агента. Закрытие окна во время поиска завершает агента.

Пример строки запуска с ручным вводом книг у двух покупателей:

```text
-gui -local-host 127.0.0.1 -agents seller1:bookTrading.BookSellerAgent;seller2:bookTrading.BookSellerAgent;seller3:bookTrading.BookSellerAgent;buyer1:bookTrading.BookBuyerAgent;buyer2:bookTrading.BookBuyerAgent
```

1. Откройте в RMA `Tools → Start Sniffer`. Выберите `seller1`, `seller2`, `seller3`, `buyer1`, `buyer2` и включите наблюдение (Sniff agents). Сделайте это до заполнения каталогов: без книг покупатели продолжают запросы каждые 5 секунд.
2. В окнах продавцов добавьте через кнопку следующие книги. Названия вводите точно, с подчёркиваниями.

| Продавец | Название | Цена |
|---|---|---:|
| seller1 | Java_programming | 700 |
| seller2 | Java_programming | 450 |
| seller3 | Java_programming | 600 |
| seller1 | Clean_code | 900 |
| seller3 | Clean_code | 650 |

3. Чтобы гарантированно сравнить все цены из таблицы, сначала заполните каталоги, затем создайте новых покупателей через `Actions → Start New Agent`: имя `testBuyer1`, класс `bookTrading.BookBuyerAgent`, Arguments `Java_programming`; имя `testBuyer2`, тот же класс, Arguments `Clean_code`. Начальные buyer1/buyer2 могли уже купить книгу в процессе ввода: перед опытом заново добавьте все книги из таблицы. Подключите новых покупателей к Sniffer в течение первых 5 секунд после создания.
4. Ожидается покупка `Java_programming` у seller2 за 450 и `Clean_code` у seller3 за 650. Покупатель удаляется после подтверждения покупки. Продавец удаляет проданную книгу из каталога. Сохраните скриншот Sniffer и консоли с фактическим результатом.
5. Создайте ещё одного покупателя на `Java_programming`. Если предыдущая покупка прошла по таблице, теперь минимальная доступная цена — 600 у seller3.
6. Запросите отсутствующую книгу `Missing_book`: видны ответы REFUSE и повторные запросы. Добавьте эту книгу продавцу — покупка произойдёт при следующем опросе.
7. Закрытие окна продавца удаляет агента и его регистрацию в DF. Проверяйте это после завершения текущей покупки: новый поиск покупателя уже не должен включать этого продавца.

Каталоги хранятся в памяти. Повторное добавление названия обновляет цену или возвращает один экземпляр проданной книги. Все цены — положительные целые числа; оплата не моделируется.

## Обмен сообщениями

```text
buyer -> все найденные продавцы : CFP (название книги)
seller -> buyer                : PROPOSE (цена) или REFUSE
buyer -> продавец с min ценой   : ACCEPT_PROPOSAL (название)
seller -> buyer                : INFORM (продажа) или FAILURE (уже продана)
```

`conversation-id=book-trade` отделяет торговые сообщения; `reply-with` и `in-reply-to` связывают ответы с конкретной попыткой. Покупатель учитывает по одному ответу от каждого найденного продавца. Ожидание предложений ограничено 3 секундами. При равной цене выбирается первое полученное предложение. Если продавец не ответил за это время, выбирается минимальная цена среди полученных предложений.

Если два покупателя выбрали одну книгу, продавец обслуживает заказы последовательно: первый получает INFORM, второй — FAILURE и повторяет поиск. При потере подтверждения уже отправленного заказа покупатель завершает работу с сообщением о неизвестном результате, чтобы не делать повторную покупку автоматически.

## Поведения и структура

| Класс / поведение | Назначение |
|---|---|
| BookSellerAgent / два CyclicBehaviour | Принимать CFP и заказы ACCEPT_PROPOSAL; `block()` при пустой очереди |
| BookSellerAgent / OneShotBehaviour | Однократно обновить каталог по действию пользователя |
| BookBuyerAgent / TickerBehaviour | Каждые 5 секунд искать продавцов через DF и начинать попытку покупки |
| BookBuyerAgent / RequestPerformer extends Behaviour | Шаги: отправка CFP, сбор предложений, ожидание подтверждения, завершение |
| BookSellerGui | Swing-форма ввода книги и цены; закрытие вызывает doDelete() |

В setup() продавец регистрирует сервис `book-selling`, в takeDown() снимает регистрацию. Покупатель выполняет DFService.search перед каждой попыткой; имена продавцов в его коде не зашиты. Одновременно у покупателя работает не более одной попытки покупки. Обновление каталога из Swing передаётся в поток агента через OneShotBehaviour.

В методичке упомянут pub/sub, но приведённый сценарий использует регистрацию сервиса в DF и периодический поиск с запросом предложений. Подписка на уведомления DF в этой реализации не используется. WakerBehaviour рассматривается в теории; для данного сценария достаточно TickerBehaviour.

## Вывод для отчёта

Проверка 29.10.2026: все исходники скомпилированы JDK 21, выполнен запуск JADE 4.6.0 без графических окон с тремя продавцами и четырьмя покупателями. Получены покупки Java_programming за 450 и затем за 600, Clean_code за 650; для Missing_book наблюдались три цикла отказов и повторного поиска. Фактический вывод сохранён в [verification/lab2-run.txt](verification/lab2-run.txt). Графические формы и диаграмма Sniffer в этой проверке не проверялись; шаги для их ручной проверки приведены выше.

В программе применены одноразовое, циклическое, периодическое и пошаговое поведения. Агенты обнаруживают продавцов через DF и взаимодействуют ACL-сообщениями. Покупатель сравнивает полученные цены и направляет заказ продавцу с минимальной ценой. Удаление книги после продажи предотвращает продажу одного экземпляра двум покупателям. Sniffer позволяет проверить последовательность сообщений и различать предложения, отказы, подтверждения и ошибки. Фактические цены и результаты опытов следует подтвердить скриншотами своего запуска.

Индивидуальная часть из Приложения А не включена: приложение и номер варианта не предоставлены.
